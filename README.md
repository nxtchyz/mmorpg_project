# MMORPG Project

Лабораторная работа по ООП на Python: игровое поле с юнитами, иерархия классов юнитов, порождающий паттерн для их создания и итератор по полю.

## Запуск

```
python main.py
```

Нужен Python 3.10 или новее, сторонние библиотеки не используются.

## Структура

```
game/
  attributes/   Health, Armor, Attack
  units/        Unit, Infantry, Archer, Cavalry и шесть конкретных юнитов, UnitKind
  factories/    UnitFactory, InfantryFactory, ArcherFactory, CavalryFactory
  field/        GameField, GameFieldIterator
main.py         демонстрационные сценарии
```

## Выбор порождающего паттерна

Выбран **Фабричный метод**.

Есть абстрактный класс `UnitFactory` с методом `create_unit(kind, x, y)` и три конкретные фабрики: `InfantryFactory`, `ArcherFactory`, `CavalryFactory`. Каждая фабрика отвечает за свой тип войск и создаёт два его вида. Какой именно вид нужен, передаётся через перечисление `UnitKind`.

Почему не Абстрактная фабрика:

- Абстрактная фабрика нужна, когда есть несколько семейств объектов, которые должны создаваться согласованно (например, «Армия Севера» и «Армия Юга» со своими версиями каждого юнита). В этой работе у юнитов нет разных семейств, у каждого вида только одна реализация, поэтому вторая ось иерархии была бы лишней.
- Фабрики разделены по типам войск так же, как сами юниты (`Infantry`, `Archer`, `Cavalry`). Чтобы добавить новый вид пехоты, достаточно изменить только `InfantryFactory`, остальные фабрики не затрагиваются.
- Код, который пользуется фабриками (`main.py`, `GameField.populate`), работает только с интерфейсом `UnitFactory` и не знает конкретных классов юнитов.

`GameField` принимает фабрику в методе `populate(factory, kind, positions)`: поле проверяет, что фабрика умеет создавать нужный вид и что для всех позиций хватает места, и только после этого создаёт и размещает юнитов.
